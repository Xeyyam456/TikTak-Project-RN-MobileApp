# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm start` — Metro dev server.
- `npm run lint` — ESLint (`@react-native/eslint-config`). No test command exists (see Working agreements — testing was deliberately dropped).
- `npx tsc --noEmit` — type-check (no dedicated script; run this directly).
- **Android, on this machine, does NOT work via `npm run android` / `npx react-native run-android`** — Node's `.bat`-spawning restriction breaks the RN CLI's gradlew invocation. Build and install directly instead:
  ```
  cd android && ./gradlew.bat app:installDebug   # PowerShell, not Git Bash
  adb shell am start -n com.tiktak/.MainActivity
  ```
- `npm run apk` — release APK via `scripts/build-apk.js` → `gradlew.bat assembleRelease`, output copied to top-level `/apk/tiktak-<timestamp>.apk`. Takes **~39 minutes** on this machine (native rebuild across all 4 ABIs) — run it backgrounded, don't assume a long quiet stretch means it's stuck.
- `npm run ios` — untested on this project so far; see Working agreements (iOS hasn't been built yet, Windows-only dev machine).
- `postinstall` runs `patch-package` automatically; `patches/react-native-screens+4.26.2.patch` fixes a `React.ComponentRef`/`ElementRef` type mismatch in a generated codegen file — don't hand-edit that node_modules file if the error resurfaces after a reinstall, the patch is supposed to reapply on `npm install`.

## Stack

React Native 0.83.10 (New Architecture), React 19.2, TypeScript, Android + iOS (iOS untouched so far, see Working agreements). Pinned above the 0.83.0 floor specifically — see Gotchas (FormData/Android regression).

- **Navigation**: React Navigation (native-stack + bottom-tabs), `react-native-safe-area-context`.
- **Gestures / sheets**: `react-native-gesture-handler` (root `Providers.tsx` wraps the tree in `GestureHandlerRootView`). `src/shared/components/BottomSheet/` is a custom drag-to-dismiss sheet (Modal + core RN `Animated` + `PanGestureHandler` on the handle only) — **not** `@gorhom/bottom-sheet` (tried, reverted; see Gotchas). `ProductDetailSheet`, `profile/OrderDetailSheet`, and `campaigns/CampaignDetailSheet` all build on top of it.
- **Keyboard**: `react-native-keyboard-controller` + `react-native-reanimated` v4 + `react-native-worklets` — see Gotchas for why `KeyboardAvoidingView` isn't used.
- **Media**: `react-native-image-picker` (avatar picker), resized at pick time (`maxWidth`/`maxHeight`/`quality`) rather than uploading full-resolution photos. `expo-image` was tried for caching and is **permanently blocked** on this RN/expo-modules-core combination — see Gotchas.
- **Splash**: `react-native-bootsplash` — native system splash is a 1×1 transparent placeholder per density bucket (deliberate, see Gotchas re: aapt2), the real animated splash (`src/shared/components/AnimatedSplashScreen/`) is drawn in JS, brand: fruit basket + "TIKTAK" gradient wordmark, authored in a fixed 170×220 viewBox scaled via `AnimatedSplashScreen.styles.ts`'s `SCENE_SCALE` — resize the mark that way, never by touching `VIEWBOX_WIDTH`/`VIEWBOX_HEIGHT`.
- **SVG**: `react-native-svg` + `react-native-svg-transformer` (import `.svg` as components).
- **HTTP / storage**: `axios` + `react-native-mmkv` v4 (Nitro Modules rewrite — `createMMKV(config)`, not `new MMKV()`, see Gotchas) + `react-native-keychain` (backs the MMKV encryption key). No AsyncStorage anywhere in the project.
- **State**: `zustand` for the basket (`src/shared/store/`), `@tanstack/react-query` + `@tanstack/react-query-persist-client` + `@tanstack/query-async-storage-persister` for server data (products/categories/campaigns/favorites/orders/profile).
- **i18n**: `react-i18next` + `i18next`, az/en/ru, `intl-pluralrules` polyfill (Hermes has no built-in `Intl.PluralRules`).
- **Notifications**: `@notifee/react-native` — local-only, no backend push exists.
- **Maps**: `@maplibre/maplibre-react-native` + OpenFreeMap's free `liberty` vector-tile style — chosen over `react-native-maps`/Google Maps specifically because Google's SDK requires a billing-enabled API key even within the free tier; MapLibre + OpenFreeMap need none.
- **Errors / crash reporting**: `@sentry/react-native`, initialized in `src/shared/config/sentry.ts` with `enabled: !__DEV__` so it never fires from a dev build.
- **Lists**: `@shopify/flash-list` — grids that render basket-dependent quantities must pass `extraData={basket}` (a PureComponent-style recycler otherwise won't re-render cells on a store change that isn't part of `data`/`extraData`).
- `docs/api.md` documents the backend contract (generated from the team's Postman collection). It has known-stale spots — the "no envelope" claims for `orders/checkout`/`orders/user`/`orders/user/:id`/`GET /basket` are **wrong in practice** (see API layer below) — and a documented double-slash quirk in the collection's `orders/user` URL. Re-derive from the collection (not old chat/session history) if endpoints change.

## Architecture

### App bootstrap (`App.tsx` → `src/app/`)

`App.tsx` is intentionally just the entry point. It imports two side-effect modules that must run before anything renders (`src/shared/config/sentry.ts` calls `Sentry.init()`, `src/shared/i18n/i18n` runs i18next's synchronous init), then wires:

1. `useAppBootstrap` (`src/app/hooks/`) — owns two gates: `tokenReady` flips once `initTokenStorage()` resolves (the MMKV encryption key lives in Keystore/Keychain, so that read is async — see API layer), `splashDone` flips when `AnimatedSplashScreen` finishes its entrance/hold/exit. The splash's animation only *starts* once `ready` (i.e. `tokenReady`), so a slow Keystore read extends the wait rather than racing the animation.
2. While `!splashDone`, `App` renders only `<AnimatedSplashScreen ready={tokenReady} onFinish={finishSplash} />` — nothing else exists yet, so `RootNavigator`'s token-based `initialRouteName` read can't race the Keystore init.
3. Once done, `App` renders `<Providers><AppShell /></Providers>`.

`Providers.tsx` nests, outermost first: `ThemeProvider` → `ErrorBoundary` → `PersistQueryClientProvider` (TanStack Query + MMKV persistence) → `GestureHandlerRootView` → `KeyboardProvider` → `SafeAreaProvider`. `ThemeProvider` wraps `ErrorBoundary`, not the reverse — the boundary's fallback renders a `<Button>` which calls `useTheme()`, so a theme context must survive even when everything below has crashed.

`AppShell.tsx` sits *inside* `Providers` (not in `App()` directly) specifically so it can call `useTheme()` for the status bar style and the React Navigation theme (`theme/navigationTheme.ts`). It renders `StatusBar` + `NavigationContainer` (ref: `navigation/navigationRef.ts`, a module-level `createNavigationContainerRef()` — needed because `httpClient.ts` has no React tree to pull a navigation prop from) + `RootNavigator` + the global `<Toast>`.

### Navigation (`src/navigation/`)

`RootNavigator` (native-stack, `headerShown: false`, `fade_from_bottom`): `Welcome` / `Register` / `Login` → `Main` (tabs) → `Basket` / `Checkout` / `OrderSuccess` / `Campaigns`, all on the same root stack so any of them can be reached from any tab. `initialRouteName` is `getAccessToken() ? 'Main' : 'Welcome'` — a synchronous MMKV read, safe only because `App.tsx` doesn't mount `AppShell`/`RootNavigator` until the async Keystore gate above has resolved.

`BottomTabNavigator` → `Home` (`HomeStackNavigator`: `HomeMain`, `CategoryProducts`) / `Search` / `Profile` (`ProfileStackNavigator`: `ProfileMain`, `AccountInfo`, `MyLists`, `OrderHistory`, `Settings`, `Support`), plus a custom `TabBar`. `HomeStackNavigator` renders `AppHeader` (the basket-icon top bar) as a sibling *above* its own `Stack.Navigator`, not inside it — it's shared chrome for the whole Home tab, not per-screen. `tabBar` is passed as a stable module-level function (`renderTabBar`) rather than the `TabBar` component reference directly, since `BottomTabView` invokes it as a plain function call outside JSX — passing the component itself would call it outside React's render pipeline and break its hooks.

Route param types live in `types/navigation.ts` (project root, not `src/`), with nested navigators typed via `NavigatorScreenParams<...>`.

### API layer (`src/shared/api/`, `src/shared/services/`)

- `httpClient.ts` — single axios instance, base URL `${BASE_URL}/api/tiktak` (`BASE_URL` in `src/shared/config/env.ts` — don't include the `/api/tiktak` suffix there). Request interceptor attaches `Authorization: Bearer` + `Accept-Language`. Response interceptor catches 401, calls `/auth/refresh` once (de-duped via a shared in-flight promise), retries the original request, and clears tokens + shows an error toast + calls `resetToWelcome()` (via `navigationRef`) if refresh fails on a genuine mid-session expiry. `/auth/*` requests are excluded from this whole flow (`originalRequest.url?.startsWith('/auth/')`) so a wrong-password login 401 doesn't trigger "session expired" handling.
- `tokenStorage.ts` — MMKV (`createMMKV({ id: 'tiktak-storage', encryptionKey, encryptionType: 'AES-256' })`), encryption key from `react-native-keychain`. **Reads are not synchronous at module load** — callers must `await initTokenStorage()` once (done in `useAppBootstrap`) before any other export is safe; `requireStorage()` throws otherwise. `getAccessToken`/`getRefreshToken`/`getRememberMe` themselves are synchronous MMKV reads once `initTokenStorage()` has resolved — only the one-time init is async.
  - **"Remember me"**: `LoginScreen`'s checkbox defaults unchecked. `tokenStorage.ts` runs `if (!getRememberMe()) clearTokens()` once at module load (i.e. only on a genuine cold start, since backgrounding doesn't reload the JS module) — this alone gives "stay logged in only until you actually close the app" semantics without a separate in-memory-only token path. Tokens are still briefly written to disk even when unchecked (cleared again next cold start) — a deliberate simplicity tradeoff.
- Three more MMKV instances exist, all deliberately **unencrypted and synchronous** (no Keystore wait) since none hold sensitive data: `settingsStorage.ts` (`tiktak-settings` — dark mode + language, survives logout), `utils/searchHistory.ts` (`tiktak-search-history`, capped at 10, case-insensitive de-dupe), `queryStorage.ts` (`tiktak-query-cache`, backs the TanStack Query persister — `queryClient`'s `gcTime` is fixed at 24h to match the persister's `maxAge`, otherwise an unused query drops from memory before it's written to disk). `queryClient.clear()` runs on logout so a different user on the same device doesn't inherit cached data.
- **Response envelope is inconsistent, and drifts over time** — most endpoints wrap in `{ message, data, result }` (`ApiEnvelope<T>` in `types/api.ts`); `docs/api.md` claims `orders/checkout`, `orders/user`, `orders/user/:id`, and `GET /basket` have no envelope, but **in practice they all now use it** (confirmed repeatedly via raw response logging while debugging real bugs — each was fixed in its `*.service.ts` to unwrap via `ApiEnvelope<T>`). Treat the docs as unreliable on this specific point: **before wiring a genuinely new endpoint, verify its actual shape with a raw log rather than trusting "no envelope" from the docs.**
- `UserProfile` has **no `email` field** anywhere (type, `GET /profile`, `PUT /profile`). The Account screen's E-mail field is a disabled, fixed-placeholder (`AccountInfoScreen`'s `PLACEHOLDER_EMAIL`) for visual fidelity to the design mockup only — never sent to the backend.
- `Product.type` (`ProductMeasure`) is a raw backend enum (`kg`/`piece`/etc.) — **never render it directly**; always wrap in `src/shared/utils/productMeasure.ts`'s `formatProductMeasure()`.
- Admin endpoints are documented in `docs/api.md` but have no service file / consumer — no admin screens exist under `src/screens/`.
- react-native-mmkv/react-native-nitro-modules are native modules — after touching their versions, a native rebuild (`gradlew.bat app:installDebug`) is required; type-checking passing doesn't mean it's linked on-device yet.

### State & data fetching

- **Basket** (`src/shared/store/`) is zustand, split by role: `basket.store.ts` (the store + actions), `basket.helpers.ts` (pure maths — `addNewItem`, `adjustItemQuantity`, `findItem`, `sortBasketItems`, `quantityForProduct`, re-exported from the store so importers are unaffected), `basket.sync.ts` (debounced network sync), `basket.toasts.ts`. `addItem` takes the full `Product`, not just an id — a brand-new basket line needs the product's price/title/image to render optimistically; an already-present line can optimistically bump its quantity without it. All call sites pass the product. Add/remove/clear are optimistic (mutate the store immediately, roll back on error) rather than waiting on the round trip.
  - `src/shared/hooks/useBasketGrid.ts` centralizes the basket wiring every product-grid screen needs (add/remove actions, per-product quantity lookup, whether the summary bar should show) — used by `CategoryProductsScreen` and `MyListsScreen`, which used to duplicate it.
  - `src/shared/components/ProductGrid/` is the shared FlashList grid itself (columns, card wrapper, empty/refresh/summary-bar-reserve plumbing) — same two screens render it with different data sources/empty states.
  - Screens still call `fetchBasket()` on mount (not just once app-wide), since the basket can change server-side between visits, but all screens read the same store so an add on one screen is instantly reflected elsewhere.
- **Everything else server-side** (`src/shared/queries/`) is TanStack Query, keyed centrally in `queryKeys.ts` so screens sharing data (e.g. `profile` is read on Home, Profile, AccountInfo, *and* Checkout) hit one cache entry instead of independent fetches. Per-domain hooks (e.g. `useCampaignsData`) wrap `useQuery`, normalizing loading/error/retry shape for the screen.

### Theming (`src/theme/`)

`colors.ts` (`LIGHT_COLORS`/`DARK_COLORS`, both satisfying `ThemeColors` — extend both together) + `ThemeContext.tsx` (`ThemeProvider`/`useTheme()` → `{ colors, isDark, setDarkModeEnabled }`) + `navigationTheme.ts` (builds React Navigation's theme object from the same palette). Per-component styling uses `createStyles(colors)` called as `useMemo(() => createStyles(colors), [colors])`, not a module-level static `StyleSheet.create`.

Defaults to `useColorScheme()` on first launch; once the user touches `SettingsScreen`'s switch it becomes a manual override persisted via `settingsStorage.ts` and stops tracking system changes. It also follows the OS theme **live** (a `useColorScheme()` effect plus an `AppState('active')` listener as a fallback — real-device testing showed the live change event can fire once per session and then silently stop, the AppState listener catches what that misses) whenever there's no override. Long-pressing the switch resets to "follow system" (`resetDarkModeToSystem`) — there is otherwise no way back once the switch is touched even once, which has caused real user confusion (see Gotchas).

### Internationalization (`src/shared/i18n/`)

Exactly two folders, no loose files: `i18n/` (setup, initialized synchronously at import time near the top of `App.tsx`) and `locales/`. Each language's strings are split two ways — `locales/<lang>/shared.json` (owned by `shared/components`/`utils`) and `.../screens.json` (owned by `screens/`) — merged via a **recursive `deepMerge()`** into one `translation` namespace (a shallow spread would let one file's top-level key silently clobber the other's same-named section). "AZN" is deliberately **not translated** across az/en/ru (ISO currency code convention). Don't resize a card/container to fit a longer translation — shrink text (`Button`'s `textStyle` + `numberOfLines={1}`) instead of growing the container.

### Notifications (`src/shared/utils/notifications.ts`)

Pure local notifications via `@notifee/react-native` — **no real backend push exists**. `notifyOrderPlaced()` (called once from `OrderSuccessScreen`) shows an immediate notification and schedules a 30-second-delayed one simulating "order being prepared," entirely client-side. Requests `POST_NOTIFICATIONS` (Android 13+) at point of use; denial is a silent no-op. `registerBackgroundNotificationHandler()` must be called in `index.js` before `AppRegistry.registerComponent`, not from `App.tsx`.

### Map address picker (`src/screens/protected/home/MapAddressPicker/`)

Opened from `AddressEditModal`'s "Pick from map" row (lives under `home/` rather than `shared/` since that modal is its only consumer). Uses `@maplibre/maplibre-react-native` with OpenFreeMap's free `liberty` style. A fixed center pin stays visually anchored while the map pans; confirming reverse-geocodes the map's center via Nominatim (`nominatim.openstreetmap.org/reverse`, requires a custom `User-Agent` header per its usage policy, light/on-demand use only). A locate-me button flies the camera to the device's real GPS position via `LocationManager`. Deep linking (`tiktak://`) was explored and fully reverted at explicit user request ("no actual use case") — don't re-add without being asked again.

## Structure & conventions

Path aliases (`babel.config.js` `module-resolver` + `tsconfig.json` `paths`, kept in sync): `@assets/*` → `assets/*`, `@shared/*` → `src/shared/*`, `@typings/*` → `types/*` (⚠️ never `@types` — collides with TS's DefinitelyTyped resolution, `TS6137`).

- **Per-component folders**: most screens/components live as `ComponentName/ComponentName.tsx` + `.styles.ts` (the `StyleSheet.create`/`createStyles` factory) + `.types.ts` (props type, if any) + `index.ts` re-exporting. External imports are unaffected (`@shared/components/ProductCard` still resolves via the folder's `index.ts`). Style-feeding constants (`CARD_WIDTH`, etc.) live in `.styles.ts`; logic-only constants stay inline in the `.tsx` — there's no `.constants.ts` split (rejected deliberately, see Working agreements). `navigation/HomeStackNavigator.tsx` and `navigation/TabBar.tsx` are the only exceptions, left flat since their styles are small.
- **`screens/<area>/hooks/`**: screen logic that would otherwise bloat a component lives in a per-feature hooks folder (`home/hooks/`, `profile/hooks/`, `search/hooks/`, `auth/hooks/`, `campaigns/hooks/`) — this is the convention **even for a single-consumer hook** (`useAvatarUpload`, `useMapAddressPicker`), don't colocate instead.
- **`src/screens/auth/`** nests its screens one level deeper, under `components/` (`auth/components/LoginScreen/`, etc.), alongside its own `hooks/` — unlike `src/screens/protected/<area>/`, where screens sit directly under the area folder. Match whichever pattern the area you're editing already uses.
- **File-size rule**: no file under `src/` should exceed ~110 lines, `.styles.ts` excluded. The two tools, in order of preference: pull sub-components into their own per-component folder, or pull logic into a per-feature `hooks/` folder. Big non-component modules split by role rather than by size (see `basket.store.ts` above). `shared/components/BottomSheet/BottomSheet.tsx` (114 lines) is the one deliberate, known exception.
- **`src/shared/icons/`** — inline SVG icon set grouped by usage (`navigation.tsx`/`actions.tsx`/`shopping.tsx`/`account.tsx`/`contact.tsx`) plus `icon.types.ts` and an `index.ts` that `export *`s all of them. **`@shared/icons` is the only import path** — never import a group file directly, an icon may move between groups. Not one file per icon, not under `shared/components/` (they're a shared asset set, not components with their own folder/styles/types). See Gotchas re: freehand brand-mark icons before touching `contact.tsx`.
- `src/shared/components/` also has a small shared-primitive layer worth knowing about: `Skeleton` (a reanimated pulse-opacity block; `ProductCardSkeleton`/`ProductGridSkeleton`/`CategoryGridSkeleton`/`SearchResultsSkeleton`/profile's `OrderCardSkeleton` all build on it) and `ScreenHeader` (the generic back-button + title bar used by pushed sub-screens like Checkout/Campaigns/AccountInfo — distinct from `AppHeader`, the persistent basket-icon bar above the Home tab's own stack).
- `types/` at the **project root** (not under `src/`) is for types genuinely shared across unrelated files: `svg.d.ts`/`images.d.ts` (ambient module decls), `navigation.ts`, `api.ts` (mirrors `docs/api.md`). A single component's own props type belongs in its `ComponentName.types.ts` instead.

## Gotchas / decisions already made (don't redo the investigation)

- **RN 0.83.0 has a core Android regression breaking all `FormData`/multipart uploads** (axios and fetch both, generic `Network Error`/`ERR_NETWORK`, no response reaches the server — facebook/react-native#54881). Fixed by using `0.83.10`+; if a *new* FormData/upload endpoint throws bare "Network Error" on Android, check the installed RN patch version before assuming an app bug.
- **`@gorhom/bottom-sheet` v5 doesn't work with this project's reanimated v4** — `present()` runs with no error but the sheet never becomes visible; downgrading reanimated to v3 is also a dead end (its Android bridge code doesn't compile against RN 0.83's New Architecture APIs). Resolution: custom `BottomSheet.tsx` (core RN `Animated` + `PanGestureHandler`). Two more traps already fixed there:
  - `Animated.event`-bound `onGestureEvent` applies raw (possibly negative) `translationY` unclamped — drive it through a plain JS callback (`translateY.setValue(Math.max(0, translationY))`) instead, clamped every frame.
  - `GestureHandlerRootView` only needs to exist once, at the app root (`Providers.tsx`). Any `TouchableOpacity` inside the sheet's `Modal` must stay core RN's, not gesture-handler's re-exported version — swapping it silently broke `flex:1`/`flex-end` layout (sheet pinned to the top, invisible, intercepting touches app-wide). Only the order-detail item list's inner `ScrollView` needed the gesture-handler swap (for scroll-lag), not the outer touchables.
- **`npx react-native run-android` fails on this machine** — Node ≥20.11/18.19.1 blocks direct `.bat` spawning. Use `gradlew.bat app:installDebug` directly (see Commands).
- **`assembleRelease` crashes aapt2 on fully-transparent PNGs** (`bootsplash_logo.png` is a deliberate 1×1 transparent placeholder per density, since the real splash is JS-drawn) — fixed via `crunchPngs false` on the release buildType in `android/app/build.gradle`. Debug builds never hit this (AGP already disables crunching for debuggable types), so "installDebug works, assembleRelease doesn't" is the signature; it can also hide until something invalidates `mergeReleaseResources` (e.g. a `versionName` bump).
- **`versionCode`/`versionName` in `android/app/build.gradle` are not derived from `package.json`** — keep them in step by hand when bumping a release, and always raise `versionCode` or the new build can't install over the old one.
- Physical device over WiFi debugging: `adb pair` → `adb connect` → `adb reverse tcp:8081 tcp:8081` (redo the reverse mapping if `Unable to load script` appears after a reconnect). Some Xiaomi/Redmi devices block `adb shell input tap/keyevent` unless "USB debugging (Security settings)" is separately enabled.
- **On this specific `xeyya`-user machine, the Gradle daemon JVM (Temurin 17) segfaulted mid-build (JIT-compiler-shaped crashes, AMD Ryzen 7735HS)** — fixed via `-XX:TieredStopAtLevel=1` + `-XX:ReservedCodeCacheSize=512m` in `android/gradle.properties`'s `org.gradle.jvmargs` (both already present). If a *build* crash recurs with a similar `hs_err_pid*.log` JIT-frame signature, check these flags are still there before re-diagnosing.
- Android 12+ splash icon is always circle-masked by the OS — worked around with a transparent 1dp `android:windowSplashScreenAnimatedIcon` in `values-v31/styles.xml`.
- Edge-to-edge (targetSdk 35+) needs `enforceNavigationBarContrast`/`enforceStatusBarContrast: false` in `AppTheme` in addition to `android:navigationBarColor` — plain color alone leaves a translucent scrim.
- **Keyboard handling uses `KeyboardAwareScrollView` (react-native-keyboard-controller), not `KeyboardAvoidingView`** — Android `adjustResize` + JS-level height/padding double-adjust and desync on close. Its `ScrollViewWithBottomPadding` wrapper hardcodes `flexGrow:1`, so a submit button placed as a sibling *outside* the ScrollView always gets pushed to the screen bottom regardless of content — keep it **inside** the scroll content if it should sit right after the form. `useReanimatedKeyboardAnimation`'s `progress.value` picks 0ms vs ~300ms scroll delay depending on whether the keyboard's already open, to avoid racing its animation.
- **Gradle SSL handshake errors on brand-new dependencies** (`certificate_unknown ... PKIX path building failed`) on this machine are caused by Avast's TLS-inspection MITM re-signing certs with a root the standalone Adoptium JDK doesn't trust (browsers/curl are fine since Windows trusts it). Already fixed via a user-writable trust store pointed to from the user's global `~/.gradle/gradle.properties` (`systemProp.javax.net.ssl.trustStore`/`trustStorePassword`) — if a *new* machine/user hits this, redo that exact recipe rather than downgrading packages to dodge it.
- **Metro's file watcher crashes on `ENOENT` if a watched directory disappears mid-scan** (Gradle CMake temp dirs, npm's package-swap temp dirs) — symptom is an infinite bootsplash hang with nothing in logcat since Metro silently died. Fix: restart Metro, add `--reset-cache` if a resolver error names a file that demonstrably exists (haste map / transform cache can go stale after rapid file churn — same class of bug hit locale JSON edits and SVG icon edits not showing up even after a full app relaunch; kill the port-8081 process and restart with `--reset-cache` rather than re-debugging the source change itself).
- **A `position:'absolute'` footer sibling can visually overlap a same-parent box even though `marginBottom`/`overflow:hidden`/`borderRadius` look correct** — `marginBottom` on a normal-flow sibling only affects the *next flow sibling*, which an absolutely-positioned footer isn't. Looks exactly like an Android "ScrollView won't clip to borderRadius" bug (only top corners rounded) but isn't — fix is keeping footers in normal flow, not chasing radius/overflow further.
- **"`flex:1` then switch to a fixed `height` on `onLayout`" must also clear `flex`**, or `flex:1`'s implicit `flexBasis:0%` keeps winning over the explicit height in Yoga's sizing. Surfaced as a box growing 2-3px when the keyboard closed.
- **Windows `MAX_PATH` (260 chars) can break New-Architecture CMake codegen builds** (`ninja: error: ... Filename longer than 260 characters`) when a native module's own long intermediate object path combines with this project's already-long absolute path. Fixed via `buildStagingDirectory "C:/rnbuild/tiktak-cxx"` in `android/app/build.gradle`'s `externalNativeBuild.cmake` (already in place) — just confirm that path is writable before re-diagnosing a new occurrence.
- `adb shell input tap` needs real device pixel coordinates, not coordinates read off a downscaled screenshot preview — scale up, and don't reuse a coordinate across screens with different layouts.
- **Android's native `secureTextEntry` visibly flashes the first typed character for ~2s** (an OS-level peek animation, not fixable via `autoCorrect`/`autoComplete`/`importantForAutofill`). Fixed by not using it at all — `Input.tsx` always renders `•`-masked text as the controlled value, diffs the incoming display text against the previous mask to recover the real typed/deleted character, and forwards that to `onChangeText`; `secureTextEntry` is always passed `false` to the underlying `TextInput`.
- **`react-native-mmkv@4`'s runtime constructor is `createMMKV(config)`, not `new MMKV(config)`** (`MMKV` is a type only in v4's Nitro Modules rewrite) — also needs `react-native-nitro-modules` as a real dependency, not just implied.
- **`expo-image` is permanently blocked** on this project's `expo-modules-core@57` + RN 0.83.10 — Kotlin compile failures in generated `Promise` interface code, a genuine upstream incompatibility. Fully reverted; don't re-attempt without confirming upstream fixed it. `@maplibre/maplibre-react-native`'s optional `expo` peer dep is unrelated and fine.
- **A native module with Kotlin (not pure-Java) implementation is meaningfully higher-risk on this RN version** — standing pre-flight check before adding one: check its Kotlin-vs-Java ratio, New Architecture support markers in `build.gradle`, `peerDependenciesMeta.expo.optional`, and get a native build to succeed before writing feature code against it.
- **A dev-build-only LogBox warning banner can dock over and intercept touches on a bottom-pinned footer button** (doesn't show up in `uiautomator dump` since it's a separate always-on-top overlay). Only in `__DEV__`. If a footer button seems untappable during manual/automated dev testing, check for a visible warning banner first.
- **Hand-drawing a recognizable brand mark (app logo/icon) as a freehand SVG path reads as something else entirely, not just "slightly off"** — a hand-drawn WhatsApp icon (bubble + freehand phone squiggle, then bubble + diagonal line) read as a "no entry" sign regardless of intent. Prefer reusing a known-correct single-path glyph over improvising for any *specific real-world brand* icon; freehand composition is fine for generic concept icons (arrows, chevrons, cart) with no single "correct" answer.
- **Prefer `navigation.reset()` over `navigation.navigate()` for any post-transaction "success" screen that must not be reachable via hardware back** — `navigate`'s implicit "pop to existing route" isn't reliable with nested-navigator params involved; `OrderSuccessScreen`'s exits both use `navigation.reset({ index: 0, routes: [...] })` for this reason.
